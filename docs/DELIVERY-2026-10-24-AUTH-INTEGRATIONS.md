# 2026-10-24 应用 OAuth、手机和签名事件

0.84 完成固定本地 A03 基线的最后三项：标准 OAuth 授权码/PKCE 与显式账号绑定、已绑定手机验证码登录、七种签名事件。此前密码、邮件、OTP、Magic Link、TOTP、Admin 和组织功能的来源未变路径复用原回执。[配置与功能合同](AUTH-INTEGRATIONS.md)、[应用协议](../contracts/application-auth-v1.json)和[脱敏验收](acceptance/2026-10-24-auth-integrations-functional.json)记录范围。当前 17 组有基础验收，10 个业务组和 3 个其他组继续；五组性能/可靠性等专项后置。这是固定本地功能基线，不是商业身份平台或短信运营商接入认证。

运维登记不可变、限项目/分支的提供商与事件目标，控制台只选择获准别名。受理时固定配置 Secret UID，运行时仅取得选中条目。OAuth 复用 Better Auth 1.7.7 的授权码、state、PKCE 与账号生命周期；OIDC 校验签名、nonce 和已验证邮箱，GitHub/Vercel 适配要求已验证资料。已有邮箱不自动绑定；显式绑定后保留 provider/subject，不持久化供应商令牌。手机号仅绑定已有应用账号，验证码原生持久化为分支 HMAC 摘要，错误次数、一次消费及发送失败回滚均有实际 PostgreSQL 验证。

`send.otp`、`send.magic_link`、`user.before_create` 阻塞交付；另外四类用户/手机/邀请事件与业务事务原子入队。事件采用分支 Ed25519 分离 JWS、有限 HTTP 重试和租约；后台交付由实际活动或应用管理员显式 drain 驱动，不提供无限重试或空闲定时轮询。应用管理员只能读取事件元数据。目标固定地址、全部 DNS 结果、TLS 主机名和响应预算；私网直连，外网 HTTPS 才使用明确配置的代理。复制或新代次清除旧挑战、丢弃待交付旧事件；同代次重试保留原配置身份和已有结果。
