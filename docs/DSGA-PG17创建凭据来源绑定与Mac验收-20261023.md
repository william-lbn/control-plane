# PG17 创建凭据来源绑定与 Mac 验收

代码提交 `e83946fe63c3114d0d5912790cbef37c076a5d7b`，仍使用自有
`codex/dsga-control-plane-v3-20261020`。当前只做PG17，其他大版本暂缓。
本批将原计划、真实SQL绑定、typed Secret读取和安全Renderer接为同一创建回调，
**尚不是完整公开worker或整个V3完成**。默认关闭，不构建镜像、不准备/执行部署、
不合main、不发布生产。

## 来源与锁约束

新增 `renderDSGABootstrap` 可直接作为生产typed创建执行器的Render回调：读取
原Operation完整计划及摘要→读取固定命名空间/名称的owned immutable凭据→
生成无副作用配置→在原Operation锁内固定或核对来源→返回config.json。
共享validateVM核对实际VM命名空间、UID、原incarnation/Compute ID及状态，随后
核对数据库已持久化VM UID，不因缓存字段或同名对象收养新实例。

DSGA凭据来源协议1要求Opaque、immutable=true、实际UID/RV、原项目/endpoint
labels，精确三键：applicationVerifier、probeVerifier、32字节controlSigningSeed。
verifier使用平台有界SCRAM格式；旧adminVerifier不回落映射成cloud_admin。
完整Data稳定排序JSON加协议域后SHA256，不忽略已登记内容。RV变化不改变内容
身份，UID重建必须拒绝。快照只保存复制后的verifier、公钥和摘要，不保留seed
或Secret指针；返回只有config.json，签名seed不进入Guest。

TLS证书不放入这份immutable凭据来源，也不在回调返回中拼入证书或私钥。实际
TLS来源绑定、挂载与轮转要由后续worker/模板独立接线；不可使用旧会改写同一
credentials Secret的TLS兜底。完整catalog尚未加入本协议，不能据三键固定就
声称全部配置来源回执完成；新协议需显式升级，未知字段不静默接受。

元数据仅追加高位迁移900000060，不改已发布058或前向join。新表
dsga_creation_credential_sources保存原Operation FK、版本、credentials UID、
32字节摘要和首次时间，不保存verifier、明文或seed。数据库禁止UPDATE（包括
无变化UPDATE）和原Operation存续时DELETE；Config UID已绑定后不许首次补认。
只允许原Operation删除后的FK CASCADE清理。此清理是DDL约束，不冒称本批已实际
验收完整删除生命周期。

锁序固定Operation→绑定→来源；Kube读取、计划读取和渲染均在SQL锁外。首次来源
只限原VM held/无执行历史且Config尚未绑定；ready恢复必须已有原来源。原来源
相同完全只读，xmin/时间不变。取得Operation行锁后检查当前lease，提交前再查；
排队期间lease过期不能因事务开始时间冻结而继续授权。COMMIT未知返回错误，由
同一原Operation重读；不覆盖冲突、不重新生成身份或凭据。总回调10秒，Kube请求
最多5秒；此绑定不授予SQL/预算/VM执行许可，后续BindConfig及UID/RV释放仍必需。

## 实际 Mac 证据与去重

使用准确 `fcada44b67d239aea8e699a721b99c470fc24d65` PG17作为独占元数据库，
该元数据库DSGA关闭、普通本地存储，不冒充Pageserver存储E2E。所有临时PG已
正常关闭。Kube侧为本机TLS API夹具，调用实际typed客户端和创建执行器，不是
真实K8s admission/etcd。工作区原始日志保留，未输出签名seed或业务verifier。

| 范围 | 实际结果 |
|---|---|
| 新增race专项 | 4顶层/18 pass事件，5.262秒，0失败/跳过 |
| 来源策略 | 10类非法输入拒绝、RV稳定、快照不保留可变指针、seed不进Guest/元数据 |
| 实际创建/恢复 | 原UID→journal→来源绑定→immutable配置→Config UID→释放；丢journal/配置回复、进程重载后同原事实恢复，来源行/xmin保留 |
| 真实前向迁移 | 模拟已登记059库，保留已有VM绑定行及xmin；新增迁移及再次migrate均通过；新库由夹具全迁移验证 |
| 变更拒绝 | 原UID下合法seed/verifier变更、同名新UID及mutable来源均不释放held，不改来源事实；恢复原来源可继续 |
| 行锁与lease | pg_stat_activity实际观察Operation锁等待，再令lease过期；等待者拒绝且无来源写入；旧worker在原来源存在时也拒绝 |
| 强化后的两个场景 | 仅same_uid_seed/verifier：1顶层/3 pass事件，3.203秒，0失败/跳过；格式合法且来源回调自身拒绝，不依赖后续配置比较兜底 |
| 实际生产反向 | 临时关闭摘要比较，same_uid_seed在指定来源断言处失败（父/子2 fail事件）；原代码逐字节恢复，随后上述两个场景通过 |
| 静态与来源 | 受影响包go vet、差异检查通过；最终484个Go/SQL/mod/sum文件摘要不变；其余3个Test函数与早期18事件版本逐字节一致 |

18与3是两阶段结果，不能简单相加当作21个独立用例或最终全仓测试。新增直接
断言只修改一个测试函数，未变函数复用初始真实结果；旧SDK、PG内核、Go/Rust
Renderer契约及控制面全量业务未重复，也不将旧SHA全量结果改标本提交。

保留失败：首次补直接断言漏了binding局部引用，只有编译失败、没有运行断言，
不算反向验证通过。修复后才执行实际摘要门禁反向，日志明确区分。临时生产改动
由包装器finally恢复，并与已通过生产文件逐字节比较；最终源码没有 `&& false`。

机器摘要、函数复用证明、原始/最终源码及日志SHA256见
[验收记录](acceptance/dsga-pg17-credential-source-mac-20261023.json)。
本批fresh fetch的Neon/Autoscaling/Neon PG17/社区PG17/自有control-plane main
均已完整包含，没有新增维护要合入；具体SHA见同一机器记录。

复验需独占PG/schema，设置NEON_V2_TEST_DATABASE_URL及v2_migration_*的
NEON_V2_TEST_SCHEMA后，使用本机SDK/Go环境执行：

```sh
go test -race -count=1 -timeout=120s ./internal/control -run '^TestDSGACredentialSource'
```

无数据库时真实用例会显式skip，不能算通过。本批已提供准确独占数据库，零skip。
