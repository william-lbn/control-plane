# 2026-10-26 原分支恢复隔离基础验收

本批完成原分支恢复所需的配置、凭据、路由与目录处理基础代码，**没有开放 reset API，没有部署 schema 070，也没有执行现有 Neon 分支恢复**。L02/L03 继续开放，固定基础验收仍为 22 组；其余五个业务组、三个运维/TLS/发行组与五个后置专项的计数不变。

完整原 Compute 配置和凭据文件存入独立不可变私有 Secret，元数据只记录引用、UID 和摘要。切换与回滚仅接受固定原 UID 和两份已保留的完整内容；丢失写入响应后读取原对象确认，拒绝同名替换、凭据漂移和第三种内容，保留其他私有文件及分支路由。原 bootstrap 回执继续不可变，新的恢复代次只在同一元数据事务完成 Timeline 切换后成为当前回执；冷启动按当前已发布代次校验。

隔离检查使用专用生成的临时 Endpoint，普通公开 Endpoint 在任何外部动作前即被排除。检查配置禁止普通目录重放并关闭 pg_cron 作业启动；公共路由先关闭，准备中的新 Timeline 保持关闭，发布后才进入 suspended。私有随机 selector 仅允许 control_probe，没有 VM 模板，不能冷创建 VM；必须明确给出规范的内部 CIDR，拒绝公开范围、跨出私有地址空间的掩码和 /0。未在本批把这些方法连接到业务恢复流程。

平台密码恢复在既有 TLS/JWT 之外增加 60 秒授权，绑定专用配置 Secret UID、完整请求/来源摘要、目标原生作用域及实际 SQL OID 观察。仅允许两条平台角色的同形凭据投影，不能夹带普通角色、数据库、删除指令、权限选项或启动项。原 Worker 租约、当前管理员、restoring 分支、全部公开 Endpoint 暂停和 SQL 检查步骤均为必要条件。审计提交在外部授权激活前完成，每次 CAS 前复查当前权限，保留原授权响应丢失的恢复语义；原通用管理网关规则保留。

目录规划依据既有不可变身份历史和历史 PostgreSQL OID。历史重命名恢复使用原对象，当前点之后才创建的对象只退休 API 意图，不向历史库执行 CREATE/DROP。当前仍有效的管理凭据保留；已撤销角色需要新代次，不能恢复旧密码。同名、OID 复用或无原始见证的对象保持未管理状态，其数据、Owner、ACL 和权限不作猜测修复。目标 SQL 事务只重绑明确证明的管理标记和密码，不创建、删除、重命名普通对象，不改变 Owner 或授权。完整观察显式包含原生注释的摘要，不能因 JSON 隐藏原注释而漏掉并发修改。

16 组唯一新增 Go/PG 检查与五组受影响检查通过，vet 通过。原生 SQL 综合项在首次专用容器发现回环 trust 认证，旧密码登录检查失去认证意义；为新临时 PostgreSQL 显式启用 SCRAM 后，复用原编译程序，只续验失败项。实际新密码登录、旧密码拒绝、原业务行及数据库/Owner OID、同一 SQL 提交重放和第三态拒绝全部通过。最后将授权收紧到生成的临时 Endpoint，并按本地固定 Neon ComputeSpec 拒绝会覆盖 GUC 的另一套存储身份/路由字段；合计复查五组本批受影响检查，没有再次计为新增；既有页面、历史分支和其他业务未重测。全部临时 PG Pod 归档后按原 UID 退休。

本批不重建或部署业务镜像，不改原有业务 Secret/PVC、Helm 发行和 Native Storage 格式；运行版本沿用 API/Worker 0.92.0 / Chart 0.9.89 / Core 193 / schema 069。070 尚未首次部署或冻结，后续完整恢复流程可继续补充。本轮没有新增对现有业务环境的 Ready/保全复验，沿用上一交付回执。
