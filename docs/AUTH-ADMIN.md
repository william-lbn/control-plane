# 应用用户管理员

应用 Admin 使用固定 Better Auth 1.7.7，协议 0.26.0。它与 Console 账号、控制面组织、数据库角色和 JWT 的 PostgreSQL 角色相互独立。分支 `admin_enabled` 默认关闭；项目管理员发布该配置后，应用端仍必须用当前分支具有 `admin` 角色的应用会话访问管理接口。Console cookie、API key、邮箱或注册顺序均不能代替应用管理员身份。

首次管理员可通过现有分支发布流程显式授予：先注册应用用户、读取其 ID，停用 Auth，然后开启管理员接口并填写“本次授予管理员的已有应用用户 ID”。此发布的 `admin_bootstrap_user_id` 必须是现有且未封禁的用户；授权与 SQL 安装代际在同一事务提交。原 Operation/代际重试不会重新授予已在应用内撤销的角色；后续新发布再次填写该 ID 才会重新授予。页面读取配置后清空这个命令输入，自动继承分支也清除授权命令。应用角色数据按普通用户数据复制，但会话、Cookie 和签名密钥仍遵守既有分支隔离。

支持创建/读取/更新/删除用户、设置角色和密码、封禁/解封、读取/撤销单个或全部会话，以及最长一小时的身份代入和退出。应用管理员不能代入其他管理员；代入期间只有目标用户权限，签名的原管理员 Cookie 只在本分支返回使用。删除需要页面明确选择目标并勾选确认；密码、会话 Token 和返回 Cookie 不展示在页面或验收摘要中。

角色/封禁字段不允许通过公开注册、自助资料更新赋值。关闭管理接口后保留原角色和封禁数据，仍阻止已封禁账号创建登录会话。封禁和会话撤销使已有会话 Cookie 失效；先前签发的无状态 JWT 仍受原五分钟到期约束，不能把会话撤销表述成所有既发 JWT 即时撤销。权限判断以现有维护库为准，管理接口返回的会话 Token 只应由授权调用方用于撤销，不能写入日志。

应用管理接口沿用维护库协议，不提供控制面 Operation 的幂等回执。页面不会自动重试管理写入；网络/5xx 结果未知时暂停后续写入，先读取用户和会话核对。Console 配置发布则继续使用原键、`If-Match` 和既有 Operation。元数据状态查看不查询用户表；主动读取/管理用户可能唤醒当前分支 Compute。

本批只补应用 Admin。OAuth、应用组织、手机号及事件仍属于 A03 后续功能，不能据此宣布完整 A03 或整个产品完成。验收结果以对应交付记录为准，性能和可靠性专项继续后置。
