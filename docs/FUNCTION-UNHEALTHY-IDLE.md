# Functions 客户进程异常时的空闲回收

## 合同与边界

启用公开 HTTP 的自动休眠策略后，客户 Node 进程退出不能让空闲实例永久占用 VM。
停止依据是与原启动和资源身份绑定、经过认证的 supervisor 调用计数和活动时间，
不是客户健康端点。此实现针对 Function Guest 内的客户进程；Kubernetes 节点分区、
旧宿主机继续执行的 fencing、TTL 及失败创建依赖清理仍属 L01 的其他闭环。

沿用现有策略接口和持久 Operation，不新增数据表或 API 路径。管理员必须确认公开
入口与后台任务回收风险，空闲时间为 30–3600 秒。后台任务没有可信计量；启用此
策略意味着它们不会阻止回收。UI 同时展示认证观察与客户就绪状态，并说明该边界。

## 调谐与身份

1. Worker 按函数 ID 进行 keyset 遍历，每批最多四个。不可观察或一直繁忙的前几项
   不会使后续函数永久失去检查机会；遍历完毕后从头开始。
2. 取得原函数的调用协调锁，重新读取当前定义、入口策略和发布实例，确认函数 ID
   一致。实际 supervisor 观察继续验证原实例身份和启动身份。
3. 仅在策略仍开启、观察成功、未 draining、活动调用恰为零、活动时间有效且已达到
   空闲阈值时发起既有自动停止意图。`NodeReady=false` 不再单独阻断该决定。
4. 活动请求、长流、观察失败、未来/空活动时间及无效策略均不授权本次停止。停止
   仍通过既有持久 Operation、权限检查、租约和正常资源退休流程完成。
5. 原函数定义、已发布 bundle、环境及受限 SQL 身份保留。下一次公开请求按既有
   冷醒通路创建新实例；正常删除只处理此次拥有的函数资源，不清除共享数据库。

cursor 只是本进程的扫描优化，没有代替数据库准入或外部 fencing。认证 supervisor
不可达时保持保守；不根据缓存 UI 的“未就绪”标签强行删除 VM。

## 新增验收

Go/PG 用例覆盖客户就绪与否、活动调用、draining、非法时间/策略、后台计量边界，
以及超过原首批范围的候选函数可达性。只复用已核对源码一致的 race/vet/OpenAPI
回执，不重复运行历史业务套件。

Linux Playwright 使用专用 `unhealthy-idle` 示例：一次正常响应后退出客户 Node，
保留 supervisor。浏览器创建并发布函数、明确开启策略，验证原实例认证观察为
未就绪且无活动调用；随后观察唯一原自动停止 Operation 完成、UI 转为 metadata-only，
再用一次公开请求验证同一定义/bundle/环境冷醒，最后正常退休专用函数并让 Writer
回到零。失败时保存原 Function/Operation/checkpoint，继续原对象，不创建替代成功。
