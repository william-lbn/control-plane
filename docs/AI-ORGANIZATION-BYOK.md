# 组织自有 AI 供应商

0.76.0 增量在已有供应商发现/修订/发布和组织额度之上增加组织 BYOK。实际功能范围见[交付回执](DELIVERY-2026-10-23-AI-ORGANIZATION-BYOK.md)。组织管理员使用自己的供应商密钥，模型仅供本组织项目/分支使用；供应商账户承担调用费用，网关不再扣平台组织额度。分支累计预算继续计量和限制供应商成本，不代表网关向组织收取两次供应商费用。

运营方必须在现有不可变公开供应商策略中明确设置 `allow_organization_byok: true`，默认停用。启用会改变策略摘要，既有动态修订须按新策略重新测试后发布。平台来源凭据及操作员权限仍与组织管理分离。组织 Owner/Admin 使用 Console 会话管理，API Key 不能管理自有供应商；拥有全局账号角色、项目 Admin 或组织管理员身份不自动成为平台操作员。

组织入口为 `/api/v1/organizations/{org}/ai-providers`，提供 capabilities、列表、详情、创建、`/{provider}/revisions`、`/publish`、`/disable` 和 DELETE。操作详情/原请求重试位于同组织的 `/ai-provider-operations/{providerOperation}`。请求/回执模型复用[原生供应商合同](AI-NATIVE-PROVIDERS.md)，管理版本 CAS、原幂等键、测试修订和发布记录继续保留。每个组织最多 16 个未删除定义，合并共享模型后目录最多 100 个模型。

BYOK 只允许新密钥或同供应商、同地址、同协议类型已测试修订的凭据复用，不能引用平台投射密钥或其他组织的凭据。原 HTTPS/精确内网白名单、固定地址、禁止重定向和密封凭据规则保留。只有运营方明确批准的实验接口可以使用专用内网测试密钥；生产密钥必须通过已有安全传输入口提交，读取接口永不回显。

定义的组织所有权在数据库中不可变，密封凭据仍绑定供应商/修订/端点身份。Worker 在探测、冻结凭据和完成前重新检查组织仍 active、提交者仍为有效组织管理员，撤权不能继续发布原操作。组织删除/停用与供应商停用使模型退出目录；历史修订和用量保留。

目录在解密密钥之前按组织过滤，SDK 凭据和 Console 调用仍需原项目/分支授权。组织私有别名可在不同组织中重复，不得覆盖共享平台别名。平台发布必须避免占用已批准的私有别名及挤满组织目录。发布和停用仍通过目录代际锁阻止旧快照继续准入。

每次请求固定保存 `billing_owner`（`platform` 或 `organization_byok`）、所属组织、供应商及修订，数据库核对已批准的模型与组织归属。费用归属不可被后续密钥轮换、发布或账本对账改写。平台静态/动态模型保持原组织额度规则，BYOK 不创建平台额度预留；未知 BYOK 用量仍保留分支预算预留。该功能未接入支付或正式供应商账单认证，成本按明确发布的固定价格估算与结算。

组织页“组织自有 AI 供应商”复用现有编辑器，提供发现、密钥轮换、模型发布和停用；切换组织时销毁前组织编辑器及内存待提交凭据。AI 模型列表和用量记录显示费用归属。完整多模态、持久引用、外部支付/账单等仍有独立交付边界。
