# 应用 Auth 删除、恢复与身份生命周期

本功能基线把已实现的 Auth、分支和项目保留生命周期放在同一矩阵中验收。实机和来源证明见 [2026-10-25 交付](DELIVERY-2026-10-25-AUTH-LIFECYCLE.md)。项目操作合同见 [保留删除](RETAINED-DELETION.md)，不是物理清除或完整灾备恢复。

| 场景 | 应用数据 | 会话与签名 | 服务身份 |
|---|---|---|---|
| 同代次安装重试 | 保留账号、密码与绑定 | 保留已签发会话、JWKS、待用挑战和原生结果 | 复用原不可变配置 Secret |
| 关闭后显式重新启用 | 保留用户、密码和账号绑定 | 新代次清除会话、JWT 签名键、验证链接和手机挑战，丢弃待交付旧事件 | 新配置 Secret；原配置保留供审计 |
| 物理分支复制 | 保留时间线中的账号、密码和原生记录 | 不接受父会话/JWT；清除复制的待用挑战和签名键 | 子分支使用独立 SQL 登录、Cookie 名称/路径与用途密钥 |
| 删除叶分支 | 保留原时间线、WAL、SQL 和配置证据 | 公共 Auth/JWKS/Token 入口关闭 | 退役自有运行时与 Compute，移除 Proxy 服务角色 |
| 删除项目 | 保留被该次删除包含的资源 | 公共入口关闭，旧 Cookie 不能继续访问 | 关闭所有被包含的服务和 Compute，写入 held tombstone |
| 七天内恢复项目 | 原资源 ID、时间线和账号数据保留；此前单独删除的叶分支不恢复 | Auth 入口继续关闭 | Auth 保持 disabled；不会自动恢复 Proxy Auth 身份 |
| 恢复后显式启用 | 原账号 ID、密码和 SQL 数据可用 | 新代次拒绝旧会话，旧 JWT 的签名公钥不在当前 JWKS 中 | 需通过原配置数据库、当前 generation 和显式操作重新发布 |

复制已启用 Auth 的父分支时，现有首次 Writer 流程会自动发布子 Auth；父 Auth 已关闭时不自动发布。显式第二因素迁移继续受 [TOTP 迁移合同](AUTH-FACTOR-MIGRATION.md)约束，不能用复制的密文直接假定可登录。OAuth/手机/事件细节见 [高级身份合同](AUTH-INTEGRATIONS.md)。

分支稳定的 TOTP、手机摘要和事件签名用途密钥，与每代 JWT JWKS、会话和随机 SQL 配置凭据分开。稳定根材料必须保留；新代次不能擅自改变已确认因子的加密材料。删除不执行未经验证的 SQL/Secret/时间线物理清扫。项目恢复不会复活撤销的 Backend 凭据或先前单独删除的分支。

当前没有单独删除分支的恢复 API、KMS 根密钥在线轮换或无损跨项目身份合并。历史时间点的完整 Backend 一致恢复归 L03，原地 reset 归 L02；可信 TLS 和完整备份/DR 另有门槛。这些边界不能由本地保留生命周期验收替代。
