# 组织 AI 额度账户

0.75.0 增量在[分支累计预算](AI-NATIVE-PROTOCOLS-BUDGETS.md)之上增加组织额度账户。额度由明确的平台运营方手工分配及更正，固定使用整数微美元；不是支付收款、现金存款或供应商账单认证。分支预算控制累计用量上限，组织账户记录实际额度支出，两者在同一准入/结算事务内处理。

账户默认不存在或停用，保留原有使用方式。只有已有供应商策略明确列入白名单的平台操作员 Console 会话可以启停账户、授信、更正和证据对账。组织 Owner/Admin 和全局账号角色不自动获得这些权限。组织管理员可以读取本组织账户及账本，组织范围的 Admin API Key 可以只读；项目范围的 Key 不能读取组织财务。

## 授信与用量

`PUT /api/v1/platform/ai-credits/organizations/{creditOrg}` 使用当前 `version`、明确的 `enabled` 和幂等键修改策略，保留原金额。`POST .../entries` 追加 `grant` 或 `adjustment`，要求来源凭证编号、操作原因和证据 SHA-256。授信为正数，更正可以正负；单次金额不为零且不超过 1,000,000 USD，累计运营授信范围为正负 1,000,000,000 USD。

原键重放返回原回执；相同组织的来源凭证编号在所有操作员之间唯一，换键或换操作员不能重复授信。更正追加新事件，不改写已经确认的调用用量。策略、授信和对账回执保留，金额事件禁止更新或删除。

启用账户后，模型必须有明确的固定价格版本；缺少价格会在调用供应商前拒绝，免费模型也必须显式使用零费率。准入先预留输入容量和允许输出的保守上界，同时保存请求、价格、组织/项目/分支身份和账本。额度不足时整笔准入回滚，分支预算不会留下半笔预留。

完整可信用量按原价格结算，释放预留差额。实际供应商用量超过声明上界时记录真实费用，允许余额为负并拒绝后续调用；不能将费用截断后宣称绝不超支。每个账户最多保留 1024 个未终结预留。未知、取消、超时和已可能接受的断流继续保留额度，过期只结束原并发占位，不自动退款。已确认发送前失败或明确未接受才可释放。

账户停用不清空费用或预留，已接受的请求继续结算。已有分支预算和组织额度采用相同的组织→分支锁顺序；供应商网络请求在准入提交之后执行。

## 查询与证据恢复

组织管理员使用 `GET /api/v1/organizations/{org}/ai-credits`、`/ledger` 和 `/requests`。平台运营方有对应的 `/api/v1/platform/ai-credits/organizations/{creditOrg}` 只读入口。账本和未确认请求按时间/ID 分页，每页最多 100 项，使用返回的 `next_cursor` 查询更早记录；游标不扩大组织范围。财务响应禁用缓存。

`POST /api/v1/platform/ai-credits/requests/{creditRequest}/reconcile` 只接纳未知或过期未终结预留，要求完整确认 Token 用量或明确供应商未接受，以及凭证摘要。它使用已保存的组织/项目/分支身份，分支已经软删除也可恢复结算。原有分支预算对账和新额度对账都会原子处理两个账本；已终结结果不可覆盖，迟到的原请求不会替换确认用量。

控制台“组织与访问控制”提供余额、授信、更正、原提交恢复、账本和未确认请求。组织自有密钥 BYOK 及其费用归属仍有独立边界，不能同时扣供应商自有账户与平台额度；在线支付、正式发票和外部账单对接继续单独交付。

部署必须先应用迁移 062，再由元数据所有者运行[最小权限授权](../tools/provision-ai-credit-grants.sql)，并确认 API/Worker/AI 均为新版本后才启用额度。网关只能读取组织归属和账户，更新使用计数/预留状态及插入调用事件；不能授信、启停策略、修改价格、读取管理回执或删除账本。旧版本不能执行新额度控制；降级前必须停用新准入并处理已接受请求，不能把普通镜像降级当成额度结算完成。
