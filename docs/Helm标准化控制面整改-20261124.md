# Helm标准化控制面整改

本次把固定三节点的创建目录扩展为冻结的1..128节点池，新增前向迁移95，不修改历史迁移或既有Operation冻结计划。完整系统当前Host Chart仍为1..16域，本轮实测5个worker，不能把控制面上限当成全系统已验证规模。

Root资源读取未确认时仍关闭业务准入。对已经完整结清的idle_source_unconfirmed关闭，暂停链路允许原准确关闭请求进行排空；API证明、Gateway和Agent必须同时核原永久预算、当前Owner、原VM/PG身份及原暂停Operation。该路径不开放业务，也不直接释放Host持有。原普通compute_suspension标记流程保持严格匹配。

Chart将runtimeSelectionNamespace、agentNamespace、runtimeAccessRolePrefix和nodeReadClusterRole作为站点输入；取消固定neon产品空间和固定平台Role引用，不增加Node写权限。平台空间沿当前原生协议要求独立neon-control-*；系统Agent仍由对应发行Chart部署到kube-system。异站点渲染及通配权限负例已通过。

依赖已绑定到正式Autoscaling提交3567f1c5076e81e754a4cea96ccf3d08f65ca3cc（v0.0.0-20261124060455-3567f1c5076e），没有开发机绝对路径replace。Go不会继承依赖模块replace，故根模块显式采用SDK已有Kubernetes 1.31.7 staging映射，避免v0.0.0占位版本造成CI不可构建。未改变既有kube-openapi版本。首次tidy因此失败、第二次因代理HTTP2下载失败的记录保留；第三次完成依赖校验、编译和真实回归。

验证为实际发布SDK编译后的262项真实PostgreSQL/网关测试全部通过，无失败无跳过，包含原生libpq/pgx凭据及新增不完整永久预算拒绝用例。228第一轮PG17/PG18公开创建、verify-full SQL、自动内存7→8→7Gi、WAL/数据、暂停恢复和最终退役均有独立证据。PG17旧安全关闭原Operation重试成功，两个版本恢复均由Kubernetes调度到其他现有节点，10000行校验和保持。

当前运行控制面镜像为neon-control-api-site@sha256:2210b82aa592242d89dffc0f9796b3a914161c0fc69bb4f715f537262a535dba，管理网关为neon-compute-management-gateway@sha256:4a144b091c90d058df7bb5facaf0d5128cdc1dd12e61ca8fd3a8bba2bdc3b5f6，仓库前缀来自站点配置。其构建发生在本次Git提交前，来源为已记录基线加补丁，不能冒称镜像标签已经对应本次提交SHA。
