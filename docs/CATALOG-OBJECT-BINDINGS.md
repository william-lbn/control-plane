# 普通目录对象的持续原生身份

本功能为角色和数据库的普通操作记录原生 OID、分支 tenant/timeline、元数据版本及角色凭据 Secret UID。目录名称和分支注释用于核对作用域，不能替代 OID。初始观测、创建确认和后续授权变更分别保留，旧记录不可更新或删除。

新建角色在原生管理请求确认后记录原创建操作的 OID；新建数据库在 PostgreSQL CREATE 确认后记录 OID。记录绑定原操作、请求摘要及有效 Worker lease。若请求结果未知且没有原 OID 记录，即使同名对象存在，也不能据此继续认领。记录完成后重试只接受同一个 OID。操作结果、目录元数据、下一代身份和成功审计在同一事务提交。

角色密码轮换只修改密码，保留原生 NOLOGIN、连接数等其他选项。改名保留 SCRAM 密码和原生 OID；相关数据库的 Owner 名称、元数据版本和已记录的身份版本同步推进。数据库 Owner 变更同时绑定数据库及原、目标角色 OID。删除保留已退休身份；经过完整删除后合法重用名称会获得新的 OID 和身份链。

已提交的旧操作仍优先恢复原不可变结果。后续改名、密码轮换、Writer 退休和凭据变化不会使旧操作重新发布历史配置或密码。

旧对象只有名称时，需要先通过现有目录身份页面完成管理员初始观测。已有 migration 049 初始观测或 migration 054 改名结果，只有与当前元数据版本、作用域和凭据代际完全一致时才能作为起点。不会把不含 OID 的旧普通操作结果推断成原生身份，也不会用当前同名对象替换已记录 OID。

此项覆盖普通自定义目录操作。分支继承的持续身份传递、原默认和系统身份漂移、Backend 名称依赖迁移仍按 C02 独立推进；并不以本项关闭整组。性能、节点分区、外部 DDL 并发栅栏及可靠性专项按用户要求后置。
