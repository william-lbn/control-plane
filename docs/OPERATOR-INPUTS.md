## 1. 后置：确实需要运营方提供的输入

| 项目 | 需要的输入 | 在输入前可完成的工作 | 尚不能证明的结果 |

## 2. 不需要额外信息：继续开发和验收

下列工作属于工程任务，不应转交给用户选择或误记为“等待凭据”：

- Functions 公共 HTTP/SSE/WS、自动休眠/冷醒、分支复制、版本回滚、触发器、日志/计量。
- Object Storage 完整 S3/SigV4、multipart/CORS、引用安全 GC、配额和独立网关。
- 完整目录/删除/恢复：rename、系统身份迁移、TTL/物理 GC、原分支恢复和 Backend 一致性。
- 小数 CPU 实际配额、完整内存归还、跨实例外部栅栏、软件 HA/DR 流程和本地全链路 TLS。
- Console 查询脚本、计划、导出、历史/保存查询和其他缺失的官网交互。

这些项目的现有代码、版本现场结果和生产门槛分别查看
[PRODUCTION-GATES.md](PRODUCTION-GATES.md)、[PRODUCT-COMPLETION-PLAN.md](PRODUCT-COMPLETION-PLAN.md)
和各功能合同。基础 Auth、对象 REST、Functions 原生执行/运行监控/显式唤醒、
自定义数据库 Owner 等已验收的切片，不代表所属整个功能组完成。

## 3. 验收与资源规则

优先新功能的最小完整 UI→API→真实服务→数据结果闭环，关联负例和必要恢复检查。
同一集群串行执行；只有具体回归风险或发布必需门槛才重跑旧套件。
保留失败及原始 fixture，按已证实 checkpoint 继续，不盲目重复写入。
完成后正常缩零/退休自有 VM/Runner/Job，归档 UID、日志与 Operation；保留数据库、
凭据、文件、PVC、WAL、对象和测试记录。硬件不足与功能缺陷分开报告。
