# Console invitations delivery, 2026-10-07

## Delivered increment

Go API/Worker, PostgreSQL migration 012, React UI and OpenAPI 0.6.0 now cover
organization invitations and invited Console account registration. Administrators
hand off an account-bound credential once; invitees choose their own password.
Existing accounts accept while signed in. Revocation, expiry, inviter demotion,
cross-organization isolation and consumption are enforced by the backend.
Membership removal takes effect on existing sessions. The UI has an explicit
member refresh action for acceptance in another browser session.

See [the API/model/security and manual UI guide](CONSOLE-INVITATIONS.md),
[Linux test commands](TESTING.md), and [full product contract](FULL-PRODUCT-IMPLEMENTATION.md).
No Python verification, credentials, private fixtures or database exports belong
in this public repository. API and Worker stay separate Deployments; this feature
does not require a permanently running Compute.

## Evidence boundary

Final candidate-source Linux Go gates passed **222 tests, zero failures and zero
skips**, including vet/race, real disposable PostgreSQL/PostgREST, migrations,
route parity, invitation concurrency and actual HTTP inviter demotion/re-promotion.
Linux frontend formatting, unit tests, TypeScript and Vite/Swagger build passed.

The candidate's Linux Chromium UI passed these six checks on 2026-10-07:

1. Admin creates an account-bound invitation; replay/list never disclose its secret.
2. Invitee registers in the UI with their own password and logs in.
3. Viewer has no invitation administration UI; another organization returns 404.
4. Existing account accepts in the UI; signup cannot replace its password.
5. Revoked invitation cannot create an account.
6. Removing membership immediately revokes organization access.

The first attempt exposed a stale member list and failed. Its partial evidence was
retained; after the UI fix, a fresh attempt passed. Do not rewrite a failed attempt
as success. Maintain private fixture/Job/Pod/operation receipts on the Linux host.
Candidate-image acceptance and acceptance of the published commit/digests are
separate steps; the unified Helm release report must record the latter.

branch, credential, timeline, PVC, WAL or object data deletion. Keep those records

## Product and production status

This is a tested self-hosted preview increment. It is not complete official Neon
parity or a production admission certificate. Console registration is distinct
from branch Managed Auth. Email delivery/verification, public signup, account
recovery, enterprise identity and external security review remain separate gates.

Managed Auth, Functions, product Object Storage and AI inference still need real
services. PITR, complete deletion/GC, fractional CPU, full memory downscale,
cross-instance scale-to-zero fencing, HA/DR, trusted TLS and persistent alerting
also retain independent implementation/acceptance gates. Data API and branch
credentials have actual implementations but need the deployment-specific gates
listed in [PRODUCTION-GATES.md](PRODUCTION-GATES.md).

Never infer feature support from running Pods, a capability schema, a disabled
stub or a previous commit's CI result. Progress toward official semantics through
the ordered service/Driver/API/UI/negative-test contracts in the implementation plan.
