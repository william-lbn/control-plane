# Functions 分支复制与恢复

F05 本地基础已验收。0.56.0 / Chart 0.9.48 / Helm 127，migration 045 已应用并冻结。七个唯一真实 Console/Neon/Guest 检查、原操作恢复及只读数据保留核对通过，见[精确交付](DELIVERY-2026-10-19-FUNCTION-BRANCHES.md)。性能和高可用专项后置。

复制固定原项目、来源分支、Function、完成部署和精确版本。只能复制同一有权限项目中的不同分支，目标必须有原生 Writer。环境复制需要明确确认；请求和回执不携带环境值。准备过程只复制不可变代码内容，在目标分支创建新的环境 Secret 和作用域 MAC、独立 SQL 角色/凭据以及新部署。原来源不变，目标完成后保持暂停，没有 VM、公开入口、日志采集或已启用触发器。

已实现显式复制、权限/版本/持久键、代码/Secret 实际校验、目标 SQL 身份和原失败操作续接，以及普通分支创建冻结快照、无 Writer 延迟准备、历史 SQL 的当前代码确认和默认停用触发器继承。实际 SQL 数据隔离与 UI 完整通过。PostgreSQL GRANT 的 warning 不被视作授权成功，事务提交前核对实际所需权限；不足时原操作给出 function_database_grant_required。

SQL 历史点与控制面代码版本分别标识。不得把当前父分支代码说成历史 SQL 点的代码；跨服务一致时间点恢复仍由 L03 的独立合同约束。复制不继承父分支的公开访问授权、输出采集授权、调用历史、实例、启动证书、SQL 密码或自动执行状态。父分支更新后，已接受复制继续使用原固定来源。

原部署和对象字节、失败历史、环境及凭据 Secret 均保留。未知初次写入结果必须查回准确 UID/MAC，重试不能覆盖同名 Secret 或用新身份掩盖旧失败。普通复制失败通过原操作的明确重试继续；发布暂停定义前验证目标受限 SQL 登录，不启动或调用客户代码。
