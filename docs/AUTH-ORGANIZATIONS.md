# 应用组织、成员与邀请

应用组织使用固定 Better Auth 1.7.7、应用协议 0.27.0。它与 Console 组织、应用全局管理员、数据库角色独立。`organization_enabled` 默认关闭；开启后仍须使用当前分支应用会话，按当前组织的 Owner/Admin/Member 权限访问。拥有其他组织或应用全局 admin 身份不会自动获得此组织权限。团队和动态自定义角色不在本协议内。

每位用户创建或加入的组织默认最多 10 个，每个组织默认最多 100 位成员；分别可配置 1–100 和 1–1000。控制面请求省略或填写 0 使用默认值，运行时收到正整数。已有成员不会因降低配额被删除；后续准入由原生事务和数据库锁检查，竞争失败不会留下空组织或消耗邀请。创建者默认 Owner，可配置为 Admin；Admin 不能删除组织。成员转移、退出、删除用户必须保留最后一位 Owner，以及没有 Owner 时的最后一位 Admin。合法的组织删除经过维护库权限检查后，在同一事务内删除相关记录。

控制台应用组织面板提供创建/更新、当前组织、成员分页、角色变更、邀请/接受/拒绝/撤销、移除成员、退出和删除。删除/退出须明确勾选确认。接口白名单固定为 22 个方法；服务端 `add-member` 捷径、团队及自定义角色接口不公开。应用全局管理员不能绕过组织权限，但可按既有受信任管理接口管理应用用户。删除唯一组织管理者会原子拒绝，不会部分删除用户、账户或会话。

邀请收件人必须登录且邮箱已验证，才能读取、接受或拒绝邀请；即使未开启自动邀请邮件也适用。邮件模式另外要求分支邮箱验证策略、运营方 SMTP 及可信来源下的固定应用接受邀请页面 URL，拒绝用户信息、查询参数和片段。服务只追加 `invitationId`、`branchId`；应用页面由应用开发者通过 AuthView 或自己的路由处理，再调用接受接口。控制台可手动填写邀请 ID。SMTP 拒绝或无法确认发送时返回 503 并回滚新邀请；邮件投递成功后事务提交仍可能失败，调用方须读取状态，不能据邮件或网络超时自动重试写入。

会话的当前组织在签发新 JWT 时重新查询成员关系，添加 `organization_id` 和 `organization_role`。成员移除后新 Token 不含旧组织声明。已有无状态 Token 最长仍可有效五分钟，不承诺即时撤销。应用授权若要求即时生效，应检查当前成员关系。

组织数据作为普通分支数据库数据复制。新分支安装会保留成员和角色，但使复制的待处理邀请失效；同一分支重新启用保留原邀请。既有会话、签名密钥及 TOTP 继承继续遵守分支合同。关闭组织管理撤销运行账号相关表的写权限，保留数据；读取配置不唤醒 Compute，主动业务请求可能唤醒。

业务写入沿用维护库协议，不提供控制面 Operation 幂等回执。页面对网络或 5xx 未知结果暂停后续写入，先读取成员和邀请核对，不自动重试。控制面配置继续使用代际、`If-Match`、原幂等键和 Operation。实际验收结论以交付回执为准；本文件描述协议，不代表完整 A03 或整个项目已经完成。
