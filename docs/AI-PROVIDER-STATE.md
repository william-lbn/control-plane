# 分支持久响应与会话

本功能为管理员明确批准的 Responses 模型提供供应商持久状态。默认继续使用无状态请求，只有模型配置的 `allow_provider_state: true` 才能保存响应、续接响应或使用 Conversations。平台只保存绑定组织、项目、分支、供应商账号及凭证版本的加密引用；提示词和模型回复不会写入明文用量台账。

原生 JSON/SSE、会话及条目管理、费用预留、引用隔离、未知结果核对和数据库权限已通过本批固定基线；实机检查与具体边界见[功能交付](DELIVERY-2026-10-25-AI-PROVIDER-STATE.md)。

## 配置与使用

在供应商模型发布页面选择 Responses，再明确勾选允许供应商持久状态。运营配置也可为已经批准的静态模型设置同名字段。关闭该能力、撤回供应商配置或变更供应商凭证版本会阻止旧引用继续使用，不会自动把它们交给新账号。

原生 Responses 入口保持 `/ai/v1/{branch}/v1/responses`，也提供 `/openai/v1/responses` 别名。通过 `store: true` 保存本次响应；返回的 `nrp_...` 可作为同一分支的 `previous_response_id`。`store` 默认为 `false`，请求中不能同时设置 `previous_response_id` 与 `conversation`。续接仍需提供新的 `input` 和已批准的模型、输出上限。流中的响应 ID、条目 ID 和响应关联 ID也会转换为平台引用。

Conversations 入口位于同一分支下的 `/v1/conversations`，支持创建、读取、元数据更新、删除，以及 `/items` 的增添、分页、读取和删除。返回的会话引用为 `ncv_...`，条目及游标为 `nit_...`。在后续 Responses 请求中使用 `conversation: "ncv_..."`，或 `{ "id": "ncv_..." }`。

这些没有 `model` 请求体字段的资源管理接口必须提供 `X-Neon-Model`，指定当前已批准的模型别名；应用凭据的模型和分支权限仍会检查。所有管理写操作还必须提供 8–128 字符的 `Idempotency-Key`。SDK 可通过其额外请求头选项设置这些头。控制台使用独立签名票据和当前项目权限，不会把控制台 Cookie 或应用凭据发送给供应商。

页面可选择持久上下文、保存本次响应、创建及管理会话、逐项删除条目、读取分页结果和删除资源。高级 JSON 编辑保持显式请求内容，不会偷偷附加页面上选择的上下文。

## 有界范围与计费

- 每分支最多 256 个未过期活动引用，每日最多创建 1,024 个；每分钟最多 60 次资源管理写操作。响应续接与会话推理仍受原有请求并发、速率、预算和组织额度限制。
- 引用有效期为 30 天，无法通过重放、改归属或改密钥延长。一次创建或追加最多 20 个内联条目，文本总量最多 16,000 字节；资源管理请求体最多 32 KiB，读取响应最多 1 MiB，分页上限 100 条。
- 元数据允许 15 个条目，键最多 64 字符、值最多 512 字符；第 16 个位置保留给服务端的所有权证明，客户端不能使用 `_neon_` 前缀。
- 上下文历史不是免费输入。费用预留继续使用模型配置的完整输入上限及本次输出上限；实际已确认用量进入原有平台费用或组织 BYOK 路径。失联和未知用量不会推断为零，也不会自动释放待核对额度。
- 原始供应商资源 ID、跨分支文件/条目引用、托管工具、后台推理和任意远程 URL 仍受原有限制；开启持久状态不会绕过这些检查。

## 未知结果与人工核对

响应引用、所用上下文引用和费用预留在同一数据库事务中受理。供应商 ID 必须先持久化，才能出现在 JSON 或 `response.created` 事件里。会话变更也会先写入操作回执；收到成功结果后保存加密回执，再对调用方确认。

供应商操作只尝试一次。超时、断连、不可验证回执或持久化失败后，保留原操作及其未知状态。同一个幂等键仅能读取已经保存的成功回执；未知结果返回冲突，不重新调用供应商。进行中的推理会阻止会话并发变更或删除。

项目管理员可以在页面核对原操作，或使用控制台的 `.../state/v1/responses/{id}/reconcile`、`.../state/v1/conversations/{id}/reconcile`。必须提供核对证据 SHA-256；丢失创建回执时，提供从供应商记录找到的原资源 ID。系统仅向原供应商执行 GET，验证原始所有权证明后找回引用，或记录管理员对原写入/删除的确认。无法证明归属的资源不会被采用，仍在执行的操作也不能提前核对。

核对历史不可删除或更改。原资源操作被核对后不会伪造出原来的成功结果；旧幂等键仍不会重发写操作。资源核对和费用核对分别保留回执，找回资源不会自动结清费用。

## 删除、恢复及供应商保留策略

本地到期会拒绝继续使用引用，并不等于供应商已清理资源。相同分支及原批准的供应商账号仍可执行显式资源删除；无法访问的旧供应商版本需要运营方依据保留记录处理，系统不会改用新密钥猜测归属。

删除供应商会话不会自动删除其中条目。若要移除条目，应先分页读取并逐项删除，再删除会话。平台不会把会话删除回执解释为所有内容已物理擦除。这遵循供应商的[会话删除协议](https://developers.openai.com/api/reference/typescript/resources/conversations/methods/delete)；删除条目返回的是经过验证的父会话回执，见[条目删除协议](https://developers.openai.com/api/reference/typescript/resources/conversations/subresources/items/methods/delete)。

项目或分支逻辑删除会撤回本地引用；恢复项目、分支复制及历史恢复不会自动激活或跨分支克隆供应商状态。物理清理、完整 Backend 历史恢复、性能和可靠性专项验收继续分别由相关功能组承担。

供应商 Responses 的默认保留时间与会话保留时间不同，历史输入仍会计费，见[官方会话状态说明](https://developers.openai.com/api/docs/guides/conversation-state)。这里的固定自托管功能验证使用独立合成供应商，不代表已经调用商业模型或验证其数据保留承诺。
