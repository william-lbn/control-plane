# 2026-10-25 Multipart checksum 功能验收

S02 固定功能基线现已完成：五种完整 checksum、最高 5 GiB 容量配置，以及七种 multipart 算法/类型组合都有实现和基础验收。**5 GiB 全量字节验证仍后置**；当前机器保留对象 64 MiB、分片 8 MiB、分支 256 MiB 的默认准入，没有冒充目标容量或生产认证。

新增九组 Go/PostgreSQL 功能检查通过：协商与请求头、严格 XML/旧指纹、独立组合算法、七种真实 HTTP 组合、5 MiB 加尾片的实际合成与拒绝/原回执、复制/覆盖/分片范围复制、升级与旧回执、列表权限/类型、损坏布局拒绝。十组具体受影响检查通过，其余原通过记录复用。Linux 编译和 vet 通过，依赖全部缓存、无新增外网下载。

实际 Boto3 1.34.46 / botocore 1.34.46 在产品入口完成七种组合、共 59 个检查点：创建、分片校验、ListParts、完成、HEAD/实际 GET/属性、复制保留策略、覆盖清除策略、重放原回执不重新发布，以及不允许的类型和错误校验拒绝。旧 SDK 模型缺少的类型/CRC64 字段通过其标准签名前钩子接入，签名仍由 SDK 完成。没有宣称该旧 SDK 的自动 composite 内容校验通过；HEAD/属性验证策略，GET 独立核对实际字节。

唯一专用新桶保留 14 条可见对象记录、七个完成上传和七片，最终可见内容仅 63 字节；原对象没有重传。自有凭据已撤销、原 Writer 已暂停。原六类存储清单的所有既有字段（包括完整 checksum）、17 张目录表摘要保持一致。格式比较仅排除新增的格式 7 列，并另验证旧列的空默认值，不隐藏旧数据变化。

部署仅更新 API/Worker 镜像。API 只构建一次，经内网复制三节点；Web/Auth/AI/Gateway 复用。Core Helm 185 / API 0.89.0 / Chart 0.9.86 / 元数据 schema 067 / 原生存储格式 7。三节点、三个 Safekeeper、七个关键组件就绪，953 个持久 Secret 身份、九个 PVC、其他六套 Helm 发行保留；Auth 工作负载均为零、Compute/VM 为零，目录 bootstrap 仍为 147。

首次旧升级测试把新空列计入旧行指纹而失败，失败记录保留；修正为排除新增列并显式验证其默认值后，该项单独通过。两个专用 PostgreSQL Pod 均先存档日志和 UID，再按 UID 退休。没有通过重建业务资源绕过失败，也没有重复未受影响的旧功能。
