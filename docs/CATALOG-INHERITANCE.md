# 首次启动保留继承目录

已验收的功能合同：新分支和新增 Compute 首次启动先只配置平台连接身份，不把客户角色、密码、数据库 Owner 或删除意图交给原生初始化。SQL 可连接后，核对实际 tenant/timeline、继承 OID、凭据 UID 和目录来源，再发布启用冷目录保护的完整运行视图。

已有可信原生身份的对象，只有原 OID、名字与 Owner 在目标分支吻合，才能传递为新分支的受管理身份。已知同名替换、缺失或 Owner 变更保留在 SQL 中，并排除出平台目录变更；不会 DROP、重设密码、改 Owner 或自动授予权限。已有排除记录继续传递。

旧来源只有名字时仍属于未建立原生身份的目录意图，不能捏造源 OID 历史。历史恢复不复制今日的客户目录。首次 SQL 核对、固定配置/凭据/路由 UID、发布确认与原操作分别留证；重试不能认领同名新 Secret，也不能把旧客户密码覆盖到后续变更。

API/Worker 0.68.0 / migration 057 的六项累计现场检查和最终保全已通过，具体范围见 [2026-10-21 首次启动保留继承目录](DELIVERY-2026-10-21-CATALOG-INHERITANCE.md)。数据分支首次 Writer 使用原分支创建时冻结的凭据代际；已有成功 SQL 初始化记录的分支替换 Writer 从首次启动跳过目录更新。旧身份链、系统默认身份、Backend 名称依赖和外部并发栅栏仍有独立范围。
