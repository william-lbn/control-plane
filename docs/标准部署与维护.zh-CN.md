# 标准部署与维护边界

完整部署由 Helm 标准站点包负责，控制面仓库提供权威 Chart、业务 API、Worker 及相关微服务源码。站点参数与发行参数分开：镜像摘要和代码来源属于发行；仓库地址、命名空间、存储类、区域、节点筛选及 DNS 后缀属于站点。运行 UID 和凭据属于当次安装，不写入复用模板。

依赖 Autoscaling SDK 时必须先提交依赖、核对远端 SHA，再固定 Go 模块版本。禁止保留构建机本地 `replace`。Neon 组合发行的源码表和可复用工作流也必须同步。

未知业务写入只观察原 Operation 或原资源；不能换幂等键或换实例重发。Root 未确认时关闭准入，恢复采用现有授权协议并校验原关闭原因、Owner、预算和实例。未经完整状态机设计与原生验证，不增加自动开放路径。

中文 README 和当前标准文档是产品入口。历史日期报告、原测试回执、摘要和已签名原件保持原字节；它们说明当次结果，不代表当前部署。已有可选产品的 API 合同仍需按各自功能审查，不把未验收功能写入核心部署承诺。

本轮不增加公网入口，不包含新增 Node、生产 HA、完整 TLS 或灾备。当前数据库核心验收不能替代这些扩展。

## 已确认的历史控制面差异

当前 PG17/PG18 的公开创建先进入受支持大版本的 DSGA Driver，使用可信运行时目录中的区域，不经过旧 PG16 创建分支。源码中的旧 PG16 分支仍有 rke2-lab 默认区域与固定筛选；它不属于当前标准验收入口，不应向用户宣传为通用部署路径。

capabilities 返回体的 cluster_id 仍是旧实验标签，属于显示元数据，不是本次部署绑定的 Kubernetes 集群 UID，也不是资源安全准入身份。后续应改为显式站点身份并重建控制面验证；本轮部署工具已独立绑定真实 kube-system Namespace UID，不能使用该显示字段替代。这个遗留问题与自动可信恢复状态机均保留为后续控制面研发项。
